# Security estimates

The scripts and raw results behind Perseus's security report: every key Perseus uses, estimated against the standard
lattice attacks and the two 2026 ring-structure attacks, Ogilvie's rotation hybrid
([ePrint 2026/279](https://eprint.iacr.org/2026/279)) and Hou-Jiang's enhanced hybrid decoding
([ePrint 2026/366](https://eprint.iacr.org/2026/366)), merged at CRYPTO 2026 as "Careful with the Ring!".

`results/summary.md` has every table (generated from the result files by `summarize.py`). The headline:

## Layout

| Path | What |
|---|---|
| `setup.sh` | fetches the two estimators at the pinned commits into `ext/` (not part of this repository) |
| `estimate.py` | one estimate on lattice-estimator 6019056: stock attacks, Ogilvie (Lemma 18), exhaustive scans, Hou-Jiang stand-ins, SPRU block model |
| `hj_estimate.py` | one estimate on Hou-Jiang's estimator (their search, or a full zeta search) |
| `run_jobs.sh` | runs a jobs file in parallel (one single-threaded estimate per line), restartable |
| `jobs/*.jobs` | the exact command lines of every result row, one file per results file |
| `results/*.jsonl` | raw results, one JSON line per estimate (`bits` = log2 cost, `s` = seconds); `dense_scans.jsonl` has one line per zeta, values rounded to 4 decimals |
| `results/moduli.txt` | output of `moduli/` |
| `results/summary.md` | every table, generated by `summarize.py` |
| `moduli/` | a small Rust program that prints every modulus from Perseus's own chain and key code |

## Running

Requirements: SageMath (we used 10.7) for the estimators, python3 for `summarize.py`, a Rust toolchain for `moduli/`.

```
./setup.sh                                                    # ext/: the estimators, pinned
SAGE=sage ./run_jobs.sh jobs/keys.jobs out/keys.jsonl 8       # any jobs file; 8 parallel single-thread jobs
python3 summarize.py out                                      # tables from a directory of results
(cd moduli && cargo run --release)                            # the moduli
```

One job is one estimate: `sage -python estimate.py <label> <logn> <logq> <secret> <mode> [sigma] [m]` (the header of
each script documents every argument and environment variable). `run_jobs.sh` writes `<out>.wall` (exit code and wall
time per job) and skips the jobs already in it, so a killed run can be restarted. To re-check one row, copy its line
from `jobs/` and run it.

## The attacks

Cost model everywhere: lattice-estimator's defaults, MATZOV BKZ cost (`RC.MATZOV`), GSA shape. Costs are log2 of the
number of operations. `m` (samples) is N, one RLWE sample, for the ring keys (what a key-switching key gives), and
unbounded for the plain-LWE TFHE keys (TFHE-rs's convention).

Standard (`est:<attack>`, the full `LWE.estimate`, each attack run alone and searched to completion):

- `usvp`: primal attack, BKZ until the unique shortest vector of the embedding lattice is found.
- `bdd`: primal attack decoding the error as a bounded-distance-decoding instance after BKZ.
- `bdd_hybrid`: guess zeta secret coordinates, decode the rest (projected CVP) for each guess.
- `bdd_mitm_hybrid`: the same with Babai decoding and a meet-in-the-middle over the guesses (Howgrave-Graham).
- `dual`: dual attack, a short vector in the dual lattice distinguishes LWE samples from uniform.
- `dual_hybrid`: dual attack with part of the secret guessed (MATZOV's FFT-based variant).
- `arora-gb`: linearisation / Groebner basis (Arora-Ge), using the bounded error support.
- `bkw`: coded BKW, combinatorial sample combination (it needs far more samples than one RLWE sample gives).

Ogilvie, "rotation hybrid" (ePrint 2026/279, Lemma 18): on Z_q[x]/(x^N + 1), each rotation x^i s of the secret is
another secret of the same lattice, so a guess may hit any of the N rotations. Lemma 18: the guessing set grows to
N |S| and the hit probability to 1 - (1 - p)^N. Our implementation (the paper has no released code) swaps exactly these
two quantities into the estimator's primal hybrid:

- `rot_nomitm`: guess-and-decode over the rotated set, Babai decoding, no MitM (|S_rot| = N |S| decodings).
- `rot_h1`: MitM, Heuristic 1: a balanced split of each rotation's set, N sqrt(|S|) decodings.
- `rot_h2`: MitM, Heuristic 2: an unbalanced split of the whole rotated set, sqrt(N |S|) decodings (the strongest).
- (`rot_cvp`: projected-CVP decoding; it never beats `bdd_hybrid`.)

Hou-Jiang, "enhanced hybrid decoding" (ePrint 2026/366): the ring structure also speeds up the decoding of the rotated
guesses, Eq. (3.2): T = (T_BKZ + N |S| T_bdd) / (p_bdd p_mitm (1 - (1 - p_S)^N)), with the number of rotations capped
where decoding would outweigh BKZ. Run with their own code:

- `egv`: enhanced guess-and-verify (projected-CVP decoding of every rotated guess).
- `ehg`: enhanced hybrid with Howgrave-Graham MitM and Babai decoding (the strongest).
- (`usvp`, `gv`, `hg`: the same estimator's non-enhanced attacks, for the validation table.)

Their attack targets sparse secrets (their Remark 1.1). For the dense keys we use two attacker-favourable stand-ins
in `estimate.py`: `hjfree` (every rotation's hit counts, but the decoding work stays that of the unrotated set: the
rotations are decoded for free, an exactly-linear-in-N gain) and `hjunit` (the same with unit-cost decoding).

## How each table was produced

Every row's command line is in `jobs/`, under the same label as in `results/`.

**Keys** (`jobs/keys.jobs` -> `results/keys.jsonl`). Per key: the eight stock attacks, the plain hybrids, Ogilvie's
three variants, the Hou-Jiang stand-ins. Labels: `dense_<chain>` main keys at Q P; `h32_n32` / `h32_n64` the sparse
bootstrapping key (h = 32) at q0 P' with sigma 3.19, `wt181_h32_n32` / `wt165_h32_n64` the same with the wide error
the client now samples (sd 3.203 * 2^t, t = 181 on the n32 family, 165 on n64); `spru_b64` / `wt181_b64_n32` the SPRU
key as a generic binary h = 64 secret; `spru_b63*` / `wt181_spru_b63*` the SPRU key's own structure (63 unknown blocks
of 1024 with one 1 each, the known block removed: dimension 64512; guesses strided over the blocks; `_r65536` /
`_r1024` with 65536 rotations, the attacker-favourable reading, or the 1024 that are distinct on a block-periodic
guess); `tfhe_*`, `pcmm`, `ccmm` the small-ring keys; `w170_h32_n32` and `h32_kp3` the wide-error equivalence check.

**Dense exhaustive scans** (`jobs/dense_scans.jobs` -> `results/dense_scans.jsonl`). The estimator's zeta search is a
1-D minimisation that need not find the global minimum. For the dense CKKS keys we also evaluate every zeta from 0
upwards (3 shards per key and attack), every Hamming weight of the guess (no early break), beta by the estimator's own
local minimum, d optimised, and stop each shard at the first zeta whose lower bound exceeds the best cost any shard has
found. The lower bound holds for any hw, beta and d: rop >= ssf(|S|) amplify(0.99, hit), hit <= |S| pmax(zeta) (union
bound; also for the rotated sets, 1 - (1 - p)^N <= N p), amplify(0.99, p) >= 0.046 / p, so rop >= 0.046 / pmax(zeta)
(no MitM) or sqrt(0.046 / pmax(zeta)) (MitM), where pmax(zeta) is the largest probability of one zeta-coordinate
prefix of the secret in the estimator's own model; pmax is non-increasing in zeta, so the stop is final (for `hjfree` /
`hjunit` the bound loses log2 N). The scans agree with the stock searches where both exist (BDD at zeta = 0 binds:
131.28 n32, 129.06 n32a4; every hybrid's minimum, the Hou-Jiang stand-ins included, lies at zeta 60-173 and
costs 158.6-187.4).

**Ogilvie validation** (`jobs/ogilvie_validation.jobs`). The paper's Table 6 sets [17], [30], [27] with our
implementation, and again with Lemma 18's hit computed in IEEE double (`FLOATHIT=1`), plus a fixed-zeta sweep of [17]'s
no-MitM cost.

**Hou-Jiang validation** (`jobs/hj_validation.jobs`). Their 16 FHE parameter sets, all five attacks, with their own
search (zeta grid of step n/100, refined +-25 by 10, d by formula) and m = oo as in their script: compared with their
`FHE_paper_estimate_results.csv` (Table 5.1).

**Hou-Jiang on our keys** (`jobs/hj_keys.jobs`). Their per-zeta cost function under a fuller search than theirs
(`SEARCH=fine`: their coarse grid, then every 25, then every zeta around the best, then a d search at the three best
zetas), m = N. For the wide-error keys we ran their estimator at an equivalent modulus rather than at sigma 2^182.7:
q0 times three special primes, 139.906 bits, sigma 3.19 (label `*_ek3`). Its modulus-to-noise ratio is 13 bits larger
than the shipped key's, so these numbers are conservative for it (`results/summary.md`, "Wide error").

**TFHE LWE keys** (`jobs/tfhe_lwe.jobs`). The binary LWE key at the shipped n 840 / sigma 2^-18 p0, the earlier
795 / 2^-17 and the precise 990 / 2^-21 sets, and the other candidates of the failure-probability frontier
(825 - 870); plain LWE mod p0, m = oo, all attacks.

## Runtimes (one core each)

- Stock attacks: usvp / dual / dual_hybrid seconds; bdd ~1 min at 2^16; bdd_hybrid 1-16 min; bdd_mitm_hybrid 2-10 min
  on the sparse keys but ~3.5 h on the dense 2^16 keys (the dense secret is modelled as weight 43691, so the hybrid
  walks ~10^4 guess weights per zeta); arora-gb and bkw 0.3-2.2 h at 2^16.
- Ogilvie on the sparse keys 3-10 min; on the dense 2^16 keys 10-13 min (no-MitM) and ~3.5 h (H1 / H2).
- Dense scans: 14-22 min (no-MitM / CVP) and 1-1.3 h (MitM) per shard, 3 shards per (key, attack).
- Hou-Jiang: one cost evaluation at 2^16 takes 25-35 s; `SEARCH=fine` 3-6 min (egv) and ~1 h (ehg) with 4 workers
  per key; their own search on the Table 5.1 sets from seconds (usvp) to 4.3 h (ehg) per cell.
- TFHE LWE: under a minute per attack. Small-ring keys: seconds to ~4 min.

## Known deviations

- **Ogilvie's no-MitM column at ring dimension 2^16 is a floating-point underflow.** Lemma 18's hit 1 - (1 - p)^N
  rounds to 0 in IEEE double once p < 2^-53, which happens at the zetas where the true optimum lies (p ~ 2^-120 for
  [17]); the search is pushed back to zeta ~60000. Computing the hit in double (`FLOATHIT=1`) reproduces the paper:
  [17] no-MitM 228.96 (paper 229.0), [30] 212.86 (212.9), [17] H2 166.99 (167.0), [27] no-MitM 130.66 (130.7). With
  256-bit arithmetic (log1p / expm1, what we report) the costs are lower: [17] no-MitM 196.0, [30] 182.2, and H1 / H2
  0.2-1.2 bits below the paper. At 2^13 the two agree.
- **Hou-Jiang's ehg column.** Re-running their code on their 16 sets reproduces every usvp / gv / hg cell and all but
  two egv cells to their two decimals; our ehg is 0.0 - 1.7 bits above their table (two cells more than 1 bit:
  1.45 and 1.69). Their published numbers come from a different machine and run; the difference is in their own
  search (zeta grid and d formula), which we run unchanged. For our keys we use the fuller search described above,
  which finds 0.1 - 1.0 bits less than their grid on the same cost function (`bits_grid` in `results/hj_keys.jsonl`).
- **bkw** raises (no finite number of samples suffices) on the dense 2^16 keys and on CCMM; **arora-gb** returns no
  finite cost on the dense keys and the TFHE keys. Neither is close to binding where it returns a cost (bkw >= 184
  bits on the TFHE LWE keys and >= 385 elsewhere, arora-gb >= 540).
- **usvp at m = oo** returns ~271 bits on two n 840 TFHE rows (beta = d = 897); at m = n it gives 140.8. It is never
  the minimum.

## Moduli

`moduli/` (Rust, path dependency on this repository's `pc-core` and `pc-tfhe`) prints every modulus from the code
that generates the keys (`results/moduli.txt`):

- Main (dense) key: its key-switching keys are at Q P, every prime of the chain (`Chain::generate` for the presets
  n32, n32a4, n32sp, n32sph, n64): 1705.341, 1733.259, 1728.548, 1729.415, 1731.000 bits.
- Sparse bootstrapping (`EncDenseToSparse`) and SPRU (`SpruAtob`) keys: one digit over the bottom level q0 and the
  first `p_sparse` special primes P' (the bottom shape): q0 P' = 307.636 bits on the n32 family, 300.000 on n64. Their
  error is `e = g 2^t + u - 2^(t-1)` (g ~ D_3.19, u uniform on t bits, sd 3.203 * 2^t) with
  t = `wide_err_shift_of(chain, q0, p_sparse)` = 181 (n32 family) and 165 (n64).
- PCMM: the chain's two bottom primes and a 31-bit special prime (`find_prime`): 86.981 bits, ring 2^12.
  CCMM: the four bottom primes and its 31-bit special prime (`CcmmKeys::special_prime`): 140.705 bits, ring 2^13.
  Their error sigma is 3.2.
- TFHE (`pc_tfhe::params::Params::new`): bootstrapping key q_br = two 26-bit primes = 51.999 bits (sigma 18.5); repack
  columns p0 P = 52.998 bits (sigma 1024); ring switch key and the binary LWE key mod p0, the chain's first prime,
  27.998 bits (sigma 4, and 2^-18 p0 = 1022.5 for the LWE key at n 840).
